P(Doom)1 -- playtest card

Keep beside the keyboard. Revised 2026-07-30. Build under test: write it here ______________________

Say these out loud -- the recording is the notes

1. At the start: the version and build hash. ("Dev build 0.13.2, 9bbadf90.")
2. Before every finding: the word BUG or the word NOTE.
3. When comparing two of anything: say V1 or V2. Never just point.

Marker words are what let the transcript be turned into a bug list with a screen-frame attached to each item. Without them every finding has to be hunted for by hand. Pointing at the screen is invisible to the recording -- this cost three unresolvable verdicts in the 2026-07-29 art session.

The run that must work

  1. Launch, customise a lab, start
  2. Hire someone through the pipeline
  3. Queue and resolve actions across several turns
  4. Fundraise at least once
  5. Drive doom to 100% and lose
  6. Defeat screen → submit → leaderboard
  7. Switch local/global, then back

Step 6 is not optional. The v0.11.0 release crashed on exactly that transition and it only reproduces in a real build.

When something breaks

  • Say BUG, then describe it while it is on screen
  • Do not fix your camera or tidy the UI first -- capture it wrong
  • Press N and file it if the game still responds
  • Note whether it is reproducible or a one-off

Crash, soft-lock, or the game not starting → league-critical. Fix, then re-cut the whole build. Never patch on top: two builds reporting the same ladder epoch while playing differently is a lie nothing can detect.
Everything else → next hotpatch window, not this build.

Afterwards

Drop the recording in art_generated\audiodump\, then: python tools\playtest_report.py art_generated\audiodump\<file>.mp4
That strips the audio, transcribes it, finds every BUG and NOTE marker, grabs the screen frame at each one, and writes a review page pairing every spoken finding with what was on screen when you said it.
