Their open question -- and I have answered it from the code

They asked: if the API was dead for four days, are those scores lost or merely invisible? They flagged it as a one-file check they had not done.

ANSWER: NOT LOST. The client spools and retries. Verified in godot/autoload/leaderboard_sync.gd:

  • _outbox_add(body) writes the POST body to user://pending_scores.json before dispatch (line 207) -- the comment says "persist FIRST -- survives a crash between here and the server ack"
  • _outbox_remove() fires only on a server ack (line 211)
  • _ready() calls _flush_outbox() (lines 51-52): "Retry anything left in the outbox from a previous session (prior crash / offline run)"

The caveat that matters: recovery requires the player to launch the game again. Someone who played once during the outage and never returned still has their score sitting on their own disk, unsent, forever. So: not a data-loss bug, but a recovery that depends on an event we do not control and cannot observe.

This is worth noting as a small win in the postmortem: the durable outbox was built for crash-safety, and it silently did a completely different job -- surviving a four-day server outage nobody knew about. Defensive work paying off in a scenario it was not designed for is rare enough to name.
